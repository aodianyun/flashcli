# FlashHub Bundle 下载可靠性

状态：PR 1 已实现并达到 Review Ready；尚未提交、合并或发布。
PR 2 已列入计划，尚未实现。

本文是英文权威规格及实现记录。中文对应文档与其范围、行为、限制和验证状态保持同步。

## 1. 问题与范围

PR 1 之前，FlashHub 下载不校验正数索引大小，没有有界重试策略，并使用固定的
临时文件路径。本次工作改进完整性校验、完整下载重试、取消处理、时间限制、临时
文件管理、最终提交和进度统计。

本 PR 仅涉及 FlashHub 下载器及其专项测试，不改变其他下载器、Bundle 选择、模型
执行逻辑或 FlashHub 索引/API 契约。

## 2. PR 1 — 已实现

### 2.1 校验、缓存与提交

- File.Size > 0 时，实际下载字节数必须与 File.Size 完全相等。超出预期时立即拒绝，
  EOF 时发现字节数不足也会失败。
- File.MD5 非空时，校验完整候选文件的 MD5。Size 和 MD5 都提供时，两项都必须通过。
- 只有所有可用校验项都通过，才复用已有缓存文件。Size 和 MD5 都缺失时，保留已有
  文件命中缓存的行为；这种命中未经完整性验证。
- 每次尝试都在目标目录创建唯一临时文件。候选响应体先完成校验，再同步写入并关闭，
  最后才重命名到正式路径。下载或替换失败时，已有目标文件保持不变。
- 每次尝试都从字节 0 开始。PR 1 不发送 Range 请求，也不复用部分下载数据。

### 2.2 重试、超时与取消

- 默认每个文件最多进行三次完整尝试，包含首次请求。
- 可重试情况包括网络连接/请求失败、响应体读取中断、HTTP 408、HTTP 429 和 HTTP
  5xx。普通永久 4xx、无效 URL、完整性不匹配和本地文件错误不会进入重试循环。
- 退避有上限且可取消。默认基准为 250 毫秒，按指数增长，最多 2 秒；HTTP 429 的
  Retry-After 会被考虑，且不会超过该上限。
- 对标准 HTTP transport，默认连接/TLS 限制为 10 秒，响应头限制为 30 秒。body 无进展
  限制为 90 秒，单次尝试总时长为 2 小时。调用方更早的 context deadline 或取消优先。
- 标准 HTTP transport 会先克隆，再设置连接和响应头限制。对自定义 RoundTripper，代码可
  限制响应头等待，但不能单独设置连接阶段超时；请求和单次尝试的限制依赖 RoundTripper
  遵守 context 取消。

### 2.3 并发与进度

- 并发调用使用各自独立的临时文件。进程内、按目标路径加锁，只保护正式目标复核和
  重命名；网络传输不串行化，也没有跨进程锁。
- 每个正式提交的候选文件都通过了该调用方提供的校验项。若校验项缺失或不足，无法
  证明内容身份。并发调用仍可能重复传输。
- 如果并发调用对同一路径使用冲突的元数据，最后成功提交的调用决定目标内容。
  PR 1 不提供目录级或版本级事务语义。
- SyncBundle 在下载期间报告实时进度。它记录各次尝试达到的最高偏移，因此重试不会
  对同一逻辑字节重复累计。已知大小的进度在下载成功前保持未完成，成功后补齐到
  索引大小。未知大小的文件不会消耗已知聚合总量。
- DownloadFile 的 Go 函数签名不变，但 onBytes 回调现在只在校验并提交成功后按有限
  大小分段报告，不再逐次报告读取到的字节。它不是实时读取回调。SyncBundle 使用
  单独的内部回调实现实时进度。

### 2.4 错误与兼容性

- 下载器错误指出 Bundle 相对文件路径、失败类别或 HTTP 状态，并在适用时包含尝试
  次数。错误不会包含原始签名 URL、URL 用户信息、query 或 token。
- Go 公开方法签名、FlashHub 索引字段、下载 URL、最终目标路径及已完成缓存布局不变。
- 下载失败不会替换已有目标文件。
- 旧路径 <dest>.incomplete 不会自动续传或删除。它可能留在磁盘并继续占用空间。
  PR 1 无法确认旧进程是否仍拥有或正在写入该文件，因此不自动清理。
- Size 与 MD5 均缺失时，PR 1 保留旧缓存行为，无法确认已有文件是否完整或正确。

## 3. PR 1 验证与验收边界

本实现的已记录验证结果：

- Windows：go test ./internal/flashhub -count=1 -v — 通过。
- Linux/WSL：go test ./internal/flashhub -count=1 -v — 通过。
- Linux/WSL：go test -race ./internal/flashhub -count=1 — 通过。
- Linux/WSL：go test ./... -count=1 -timeout 900s — 通过。
- git diff --check — 通过。

以上为已记录结果，并非本次仅修改文档后重新运行的测试。本次整合没有改动 Go
实现和测试文件。

PR 1 的验收范围仅限于本文描述的能力：对可用元数据进行完整性校验、有界的完整下载
重试和超时、安全的临时文件提交、进度统计及错误脱敏。PR 1 不要求任何续传能力。
